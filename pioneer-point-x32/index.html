X32 Field Guide

Pioneer Pointe — two X32s (FOH + monitors) on a hybrid analog-split / digital-snake rig.

Written from documentation, not from experience. Zach is the engineer; this is a fast-recall sheet, not a second opinion. If it contradicts what you're hearing in the room, trust the room.

1The rig — how the split actually works

Seismic analog splitter → one leg to the monitor desk, one leg to an S32 → FOH over AES50 A.

stage mics / DIs
      │
      ▼
Seismic passive splitter  (SARMSS-32x515)
      │
      ├── leg 1 ─────────────────▶  monitor X32   (its OWN local preamps)
      │                                  └─▶ wedges / IEMs
      │
      └── leg 2 ─▶ S32 stage box ─ AES50 A ─▶  FOH X32
                                             └─▶ Main L/R ─▶ amps ─▶ mains + subs

The split is analog, and it happens before any preamp. That single fact is what makes this rig behave the way it does:

  • ✓ Each console has its own preamps. The monitor desk uses its local inputs; FOH's preamps live in the S32. Gain is fully independent — ride gain on monitors to kill feedback and the FOH mix doesn't move. This is not how a shared-stage-box rig behaves.
  • ✓ No clock relationship between the desks. Only FOH is synced over AES50, to the S32. The monitor desk is standalone on its internal clock.
  • ✓ Failure isolation. Either desk can crash and the other keeps working. If AES50 A drops, FOH goes down and monitors keep running — the band still hears themselves while you fix it.
⚠ The S32's outputs belong to FOH

The S32 is fed from FOH's AES50 port, so its analog outputs are FOH's. Wedges come off the monitor X32's own XLR outs — never the S32. Patch a wedge to an S32 output and the monitor desk will look completely correct while making no sound: meters move, sends look right, silence.

Two sets of preamps means two gain structures. Channel numbering has to match on both desks — so "gtr 2 is ringing in wedge 3" means the same thing to both of you — but the gain values won't read the same, and that's correct. Don't "fix" one to match the other.

The only thing the two desks physically share is the mic signal and phantom power, which is what the next section is about.

The PA side — crossover lives in the boxes

There's no DriveRack in the chain, so FOH's Main L/R goes straight to the amps. That's fine, because the subs and the line arrays have their own crossovers built in — nothing on the desk needs to split mains from subs.

The subs and mid fills are aux-fed — they come off mix buses on the FOH desk, not off Main L/R, so you choose what goes to the subs rather than sending them the whole mix. Three things follow from that:

  • The Main LR limiter doesn't cover them. They never pass through Main L/R. This is handled — there are compressors on those auxes acting as limiters — but see the note below on setting them so they actually limit.
  • The Main LR insert GEQ doesn't reach them either. System EQ for subs and fills has to live on those buses.
  • Mid fills need delay. They're closer to the audience than the arrays, so their sound arrives early and has to be held back. See below — the current setting needs rebuilding.
Delay — set, with the math kept for reference

Delay only does something relative: it's the difference between sources that matters, so the same value applied to everything cancels out and just adds latency. Mains are the reference at zero; the fills are held back to match them.

delay (ms) ≈ distance (ft) × 0.89 at ~70 °F, where sound travels about 1125 ft/s. So 20 ft = 17.8 ms. (Sound moves faster when it's hot — ~0.87 ms/ft on a 90° afternoon. Irrelevant over short throws, matters for a real delay tower.)

Aligning subs by ear: play steady low end, flip the sub polarity and tune delay for the deepest null, then flip polarity back — where it cancels hardest reversed is where it sums hardest forward. On fills, add ~10 ms past the measured figure so the precedence effect keeps the image on the stage.

Two buses, opposite pre/post answers

Sends to the aux-fed sub and fill buses want POST-fader — so pulling the kick fader down pulls it down in the subs too, and one fader move keeps the mix coherent. Pre-fader and you'd be mixing the same source in two places all night.

But the monitor buses want sends PRE-fader (section 5). Same console, same menu, opposite correct value. Know which bus you're looking at before you change a pre/post setting. Bus output taps stay post-fader either way, so the bus master fader still works.

⚠ A compressor is only a limiter if it's set like one

The comps on the sub and fill auxes are the only thing protecting those drivers now that the DriveRack is gone. Worth confirming they're set to actually limit:

Detection = PEAK, not RMS. This is the one that matters most — RMS averages over a window and sails right past the fast transient you're trying to catch. Then ratio as high as it goes, fast attack (a slow attack lets the loudest part of the transient through, which is the part that does damage), hard knee, and a threshold set at gig level with the real amps.

A comp sitting at 4:1 with a 30 ms attack and RMS detection feels like protection and isn't. Same reasoning applies to the Main LR comp covering the arrays.

The arrays have an EXT SUB switch that engages their high-pass when an external sub is covering the bottom. That's set — nothing to do with it on the desk.

Sub polarity switch (0 / 180). Most powered subs have one, and it matters at the crossover point where arrays and subs overlap. If the low end sounds thin or scooped right around the crossover, flip it and keep whichever is louder there. Aux-fed makes this easy to test: solo the kick, walk the crossover region, flip the switch, keep the louder one.

2Phantom power & grounding

The splitter is a Seismic Audio SARMSS-32x515 — a hardwired passive Y. No isolation transformers, no ground-lift switches.

⚠ Phantom passes to everything

There's no transformer to block DC, so +48V from either side reaches the mic and backs into the other side's preamp inputs.

So, before doors:

  1. Exactly one side sends +48V. Not both, not "probably neither."
  2. Decide which: the monitor desk's local preamps, or the S32's preamps on the FOH leg. Note that on the FOH side the phantom is coming from the stage box, not the console.
  3. Tell your monitor engineer explicitly. Agree out loud. Don't assume.

If both sides send it: two supplies fighting each other through a hardwired split. Best case redundant; worst case noise and intermittent weirdness on condensers and active DIs that'll eat twenty minutes at line check.

The bigger passive-split issue: grounding

No transformers and no ground-lift switches means the two desks are galvanically tied together through the snake. Both audio grounds are one ground.

  • Put both desks on the same power distro / same circuit if there's any way to do it. Different circuits at different ground potentials = hum or buzz through the split, and there's no lift switch to break it.
  • If you get hum and can't share a circuit, the fix has to come from somewhere else: DI boxes with a ground lift on the offending sources, or an isolation transformer inline. The snake won't help you.
  • Sort this at load-in, not at line check. It's a power-distro decision and it's much harder to fix once everything's run.

Minor: parallel input loading

A passive Y puts two preamp inputs across one mic, so the mic sees roughly half the load. With bridging inputs this is a non-issue — still comfortably above what a 150–200 Ω mic wants — but it's why you may read a hair less level than a single-desk setup. Don't chase it as a fault.

3Head amps — where FOH gain really lives

FOH's head amps aren't in the desk. They're the S32's preamps, driven remotely over AES50 A — knob at FOH, actual analog gain in the box on stage.

First thing to check: is Gain Split engaged?

The X32 has a Gain Split mode. When it's ON, the channel strip's gain control becomes a digital trim, ±18 dB only — it is not touching the S32's analog preamp. The real head amp gain moves to SETUP → Preamps and can only be set there.

That matters because if Gain Split has been on, then setting "preamp" on the channel strip has really been riding an 18 dB digital window — while the S32's actual analog gains sat wherever they were last left. Channels can be badly under- or over-driving the S32's converters while looking completely reasonable on the desk.

Three things to look at

  1. Is Gain Split engaged on the FOH X32?
  2. What are the actual S32 analog gains sitting at, on SETUP → Preamps?
  3. Is HA Gain Remote off? That setting lets another console drive your gains over AES50 — and nothing else is on AES50 in this rig.
Recommendation for this rig: turn Gain Split OFF

Gain Split exists so two consoles can share one stage box — one takes the analog gain, the other gets trim. This split is analog. The monitor desk has its own preamps and never needed trim, and nothing is competing for the S32. With Gain Split off, the FOH channel knob drives the S32's real head amp directly — which is what you probably think it's been doing all along.

Do this before dialing anything else. Every gate threshold, compressor threshold and limiter setting on the desk is referenced to gain. Audit the head amps first, then dial — otherwise you set it all twice.

While you're in there, per channel: check low-cut / HPF (engaged? at what frequency? easy to leave on from a previous show), phase / polarity invert, and anything sitting at an extreme — channels pinned near 0 or +60 usually mean someone set it weird rather than set it deliberately. The S32's preamps can also be touched from its own front panel, so give the box a look if the FOH readings don't match what you're hearing.

4No audio — the fast tree

Work top to bottom. Don't skip — the answer is almost always higher up than you think.

  1. Is signal hitting the desk at all?
    • Meter on the channel strip — any movement?
    • Gain up? Phantom on, from whichever side owns it (section 2)?
    • No meter → the problem is before the console: cable, mic, splitter, stage.
  2. Is the channel getting the right source? (different answer on each desk)
    • Monitor desk: ROUTING → Inputs should be Local — its own XLR ins off the splitter.
    • FOH desk: ROUTING → Inputs should be AES50 A — the S32. Not Local; nothing is plugged into FOH's own XLRs.
    • Getting these backwards is a fast way to have one desk stone dead at line check.
    • Channel Config → is Source the input you think it is?
  3. Is it muted somewhere you're not looking?
    • Channel mute
    • DCA mute — a muted DCA silences its members even with the channel unmuted
    • Mute group — the sneaky one
  4. Is it going to the main bus?
    • Channel Home → Main LR assign is ON
    • Channel fader actually up
  5. Is Main LR getting out of the box?
    • Main LR fader up, not muted
    • ROUTING → Out 1-16 — is Main L/R actually patched to the physical XLR outs you're using? This is the one that gets people: meters dance on the desk, nothing comes out of the PA.
  6. Signal leaves the desk but the PA is still silent? It's the amps or the cable.
    • There's no DriveRack in the chain anymore — the desk out goes straight to the amps, so there's no processor in between to mute you or clamp you down.
    • Amps powered? Gain knobs up? Input cable seated at both ends?
    • Amp in protect / thermal? Most will show it on a front-panel LED.
  7. Still nothing?
    • Solo/PFL stuck on somewhere? (Check the solo clear.)
    • Headphones work but XLR out doesn't → it's an output patch problem on the desk, guaranteed. Back to step 5. (If the desk out is clean, it's downstream — cable or amps, step 6.)
Bus has signal but no output — split it fast

Does the bus master meter move? Send meters only prove the channel feeds the bus. Meter still → it's inside the desk: fader, mute, pre/post, bus config. Meter moving → it's the output side: output patch, or a wedge wrongly patched to an S32 out.

Bus fader does nothing but signal passes anyway → output tap. ROUTING → Out 1-16, check the tap next to the source. A pre-fader tap sits upstream of the bus master, so the fader is decorative.

5Monitor desk

Its own desk, its own preamps, its own outputs. Each wedge / IEM is one mix bus (Mix 1, Mix 2, Mix 3…), and each bus is one person's monitor.

If you already run a QU32, you already know this workflow — the X32 just labels one button differently. On the QU you hit a Mix master button and the faders flip to show that mix's levels; you fly the faders to build that person's wedge, then hit the next Mix and do the next person. The X32 does exactly the same thing:

This is your mix-on-faders workflow — the X32 button is "Sends on Fader"

Press Sends on Fader, select the mix bus for that person's wedge, and your channel faders become the sends into that one wedge. Build it, then select the next bus and the faders become that wedge's sends. One wedge at a time, faders the whole way — identical to hitting Mix 1, Mix 2, Mix 3 on the QU.

Why "pre-fader" matters — it's what makes that workflow behave: the faders you fly in that mode are the sends, and those sends need to be pre-fader. That's the setting that keeps each wedge independent: when you're in Mix 3 and pull the vocal down, it drops only in Mix 3 — Mix 1, 2, 4, 5 don't move. If a bus is set post-fader instead, the sends get chained to each channel's main fader and the wedges start dragging each other around. Your QU defaults to pre-fader for monitor sends; on the X32 you set it yourself, so check it.

Note this has nothing to do with FOH. Two separate consoles with separate DSP means FOH fader moves can never reach the monitor mixes — and with an analog split that's doubly true. Pre-fader matters inside the monitor desk.

  • Channel sends to the monitor buses: pre-fader — so the wedges stay independent (this is the whole ballgame)
  • Bus output tap: post-fader, so the bus master fader still sets that whole wedge's volume — "turn the drummer's wedge down" is one fader, the Mix bus master
  • Limiter on every monitor bus, threshold below −3 dBFS — cheap insurance against a dropped mic or a feedback squeal going straight into someone's ears
  • The channel's own fader (normal view, not Sends-on-Fader) does almost nothing here — park it at unity and leave it
⚠ Two pre/post settings that want opposite answers

Sends pre-fader, output tap post-fader. Two different settings at two different points, and they want opposite values. This is the live trap in this rig and it's easy to set wrong while you're chasing a no-output problem.

6Scenes & safes — the festival killer

Multiple bands = multiple scene recalls = the chance to nuke your PA between sets.

When you load a band's scene, by default it can overwrite routing, output patch, and preamp gains. Load the wrong scene and the house goes silent — mid-changeover, with an audience.

Two kinds of safes, and the difference matters

TypeScopeUse
Scene Safes ⚠ Per-scene, NOT global Set on each scene individually. Easy to forget one.
Channel / Parameter Safes ✓ Global — apply to every recall This is what you want for festival protection.

Set global safes before doors

  • Routing I/O — so a scene recall can't repatch your inputs
  • Output Patch — so a scene recall can't disconnect your PA. There's nothing downstream to save you now that the DriveRack is gone.
  • Preamp (HA) — so a scene recall can't blow up the gains you just spent section 3 auditing
  • Main LR insert — so a recall can't drop your system EQ
  • Consider safing mutes on input channels, so a stale scene can't mute something live

Then a band's scene recalls their channel processing (EQ, comp, mix) without ever touching the infrastructure keeping sound in the room.

Between bands

  • Save a scene per band, named clearly
  • Save the show file to USB — and do it again after you finish tweaking at soundcheck
  • If a recall goes wrong: don't panic-fix twenty things. Reload your known-good scene.

7Before you leave the house

Head amps come first

Every gate, comp and limiter threshold on the desk is dialed relative to gain. The three head-amp checks below come before anything else on this list — audit gain first, then dial, or you'll set it all twice.

  • Both X32s on the same firmware (mismatches cause weird show-file behavior) — and the S32 on matching firmware too
  • Show file saved to USB, and a second USB with the same file
  • Head amps ① — Gain Split checked on the FOH X32. If it's on, the channel knob is a ±18 dB digital trim, not the S32's preamp. Recommend off (section 3).
  • Head amps ② — actual S32 analog gains reviewed at SETUP → Preamps, not just the channel strips
  • Head amps ③ — HA Gain Remote off. Nothing else is on AES50 in this rig.
  • Per channel: phantom state, low-cut, phase invert, nothing pinned at an extreme — and check the S32's own front panel, its preamps can be set locally on the box
  • Agreed with monitor engineer: who sends phantom — exactly one side, passive Y split
  • Both desks on the same power distro if at all possible — no ground lift on this snake
  • FOH inputs set to AES50 A, monitor inputs set to Local — the two desks are sourced differently
  • Wedges patched to the monitor desk's own outs, not the S32's
  • Main LR limiter armed — no DriveRack downstream anymore, so the desk is the only thing between a feedback squeal and your drivers
  • Sub polarity checked at the crossover (section 1)
  • Sub / fill aux comps verified as limiters — PEAK detection, high ratio, fast attack, threshold set at gig level
  • Delays confirmed — mains at 0 as the reference, fills held back to match
  • Identical channel order on both desks — so "gtr 2 is ringing in wedge 3" means the same thing to both of you
  • Spare XLRs, spare USB, headphones
